# 授權與資安前提

這份不是法律意見。開案前請客戶的法務或你的律師看過合約條款。

## 反編譯的授權問題

REA 的 DISCLAIMER 明寫：只限分析你擁有或獲授權檢視的軟體。
商用 ERP（鼎新、正航、SAP B1、Oracle 等）的授權合約通常有「禁止反向工程」條款。

處理方式，依風險由低到高：

1. **不碰商用軟體本體。** 只分析客戶自己開發的外掛、報表、整合程式、資料庫 schema。這些是客戶的資產。多數盤點案這樣就夠了。
2. **只做黑箱觀察。** REA 的 process capture、HAR / 封包分析、DB schema 讀取，都不涉及反編譯。看系統「做了什麼」而不看「怎麼寫的」。
3. **取得原廠書面同意。** 若真的要反編譯商用軟體，請客戶向原廠取得書面同意，並附在合約附件。
4. **互通性例外。** 部分法域對「為了互通性而進行的逆向工程」有例外，但台灣著作權法的適用範圍要問律師，不要自己判斷。

## 合約裡要寫的

- 客戶聲明對分析目標擁有所有權或授權，並承擔第三方授權責任
- 分析範圍以 `specs/` 為準，範圍外不做
- 所有分析在客戶指定環境內執行，顧問不帶走 assembly、資料庫檔、封包檔
- 交付物清單（盤點報告、訪談紀錄、tool 草稿）
- 訪談紀錄的保存與銷毀期限

## 資安操作規範

- 分析機器：客戶提供，或你的機器但只接客戶內網、不接外網
- 雲端 agent：只允許處理黃 / 綠等級資料，且需去識別化；紅等級一律本機
- 唯讀帳號：見 `db-mcp.md`
- 封包捕捉：事先告知客戶 IT，只在測試環境或指定時段
- 結案：刪除本機所有客戶資料副本，留書面紀錄

## REA 工具本身的授權

REA 是 MIT。但它呼叫的 Hopper、IDA、JEB 是商用軟體，要自己買授權，試用版有輸出分享限制。
Ghidra 是開源的，優先用。
