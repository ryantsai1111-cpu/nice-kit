### 工作流程（本 pack 在核心流程中插入的步驟）

| 階段 | 怎麼觸發 | 產出位置 |
|---|---|---|
| 驗收測試 | 載入 `e2e-from-spec`，輸入 `specs/<feature>/spec.md` | `e2e/<feature>.spec.ts` |
| 實作 | superpowers；每個任務以對應的 e2e 通過為完成 | `src/` |
| 看畫面 | Playwright MCP 開本機 dev server 實際操作 | 不產出檔案 |

順序：規格 → 計畫 → 驗收測試（先紅）→ 實作（變綠）。沒有 e2e 的功能不算完成。

### 看畫面的規則

- 宣稱 UI「做好了」之前，用 Playwright MCP 實際開過頁面，附截圖路徑或描述。
- 改 CSS / 版面的任務，看手機寬度（375px）與桌面各一次。
- 不要只看 build 有沒有過。

### 不要做的事（補充）

- 不要把 `.env` 內容、API key 寫進前端 bundle。
- 不要在 e2e 裡寫 `sleep`；等元素，不等時間。
- 不要為了讓測試過而改測試的斷言；先確認是測試錯還是程式錯。
