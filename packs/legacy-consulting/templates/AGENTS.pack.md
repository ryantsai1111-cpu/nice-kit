### 環境

- 分析目標位於：<路徑或主機>
- 所有分析只在客戶環境內執行，**不得**把 assembly、資料庫檔、封包檔複製到外部。
- 資料庫帳號：唯讀。任何需要寫入的操作一律停下來問。
- 原始碼：<有 / 部分 / 無>。有的部分用 repomix 先讀，沒有的用 REA。

### 工作流程（本 pack 在核心流程前後加的步驟）

| 階段 | 怎麼觸發 | 產出位置 |
|---|---|---|
| 訪談 | 載入 `grill-the-client`（或說「訪談客戶」） | `.grill/` |
| 盤點 | REA MCP / DB MCP / Playwright MCP（只有網頁可登入時） | `inventory/` |
| 補缺 | 載入 `inventory-gaps`，再回到訪談 | `.grill/gaps-*.md` |
| 行為封存 | 載入 `characterization-tests`，在實作前跑 | `tests/characterization/` |

順序：訪談 → 規格 → 盤點 → 補缺 → 計畫 → 行為封存 → 實作。階段之間不跳。

### 證據來源（補充核心規則）

- 關於客戶系統的結論：REA 的 evidence 區塊、DB schema 查詢、或 `.grill/` 訪談紀錄的檔名。
- 盤點報告的每一節末尾列出「未知項」，不准省略。

### 資料敏感度

| 等級 | 定義 | 處理 |
|---|---|---|
| 紅 | 個資、薪資、客戶名單、財務明細 | 只記錄表名與欄位名，不讀內容；不進任何雲端 agent |
| 黃 | 內部流程、設定、程式邏輯 | 可在本機 agent 處理；雲端需去識別化 |
| 綠 | 公開資訊、技術文件 | 不限 |

不確定等級的一律當紅處理，列入 `inventory-gaps` 待確認。

### 本地 / 雲端分工

| 步驟 | 跑在哪 | 理由 |
|---|---|---|
| 盤點（REA、DB MCP、封包） | 本機 agent | 碰到紅、黃資料 |
| 行為封存（錄舊系統輸出） | 本機 agent | 輸出含真實資料 |
| 規格、計畫、文件產出 | 雲端 agent 可 | 只碰去識別化後的描述 |
| 實作 | 依程式碼是否含紅資料決定 | 預設本機 |

### 不要做的事（補充）

- 不要在訪談階段提解決方案。
- 不要對生產資料庫執行任何非 SELECT 語句。
- 不要在未確認授權前反編譯商用軟體；依據見 pack 的 `docs/legal.md`。
- 不要把受訪者姓名寫進任何產出。

### 交付物

- `inventory/report.md`：盤點報告（架構、資料流、敏感度分類、未知項）
- `inventory/tool-layer-draft.md`：建議的 MCP tool 介面草稿（若在範圍內）
- `tests/characterization/`：舊系統行為基準，新系統驗收用
- `.grill/`：全部訪談紀錄（交付給客戶作為稽核軌跡；交付前先檢查姓名與個資）
